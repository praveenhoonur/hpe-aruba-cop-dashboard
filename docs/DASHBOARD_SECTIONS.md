# On-Prem Debugging Tool — Dashboard Section Reference

This file documents every section/panel of the dashboard UI and what it is
used for. It is intended as a reference for operators and reviewers and is
marked **read-only** (file mode `444`) to prevent accidental edits; change
the mode (`chmod u+w`) deliberately if this document ever needs updating
alongside a UI change.

---

## Home page (`index.html`)

### 1. Download Debug Script
Provides a direct download link (and a "View source on GitHub" link) for
`k8s-debug-session.sh`, the Kubernetes/COP debug-session script that
operators run on-prem to collect `cop_sanity_logs*.log` bundles for upload.

### 2. Upload Log File
File-upload form for submitting a collected log bundle for analysis.

- **Accepted file types:** `.log`, `.txt`, `.tar`, `.tar.gz`, `.tar.zip`/`.zip`
- **Button:** "Upload & Analyse" — submits the file to `POST /upload`,
  which parses it (and, for archives, extracts and analyzes the contents)
  and renders the Executive Summary + Detailed Analysis tabs below.
- **Reset** clears the current analysis and returns the page to its
  empty/initial state.

### 3. Executive Summary (`#execSummary`)
Rendered only after a successful upload. Gives a one-glance, high-level
verdict on cluster health:

- **Verdict banner** — overall status (`error` / `warn` / `info`) with a
  plain-English summary sentence (e.g. "3 errors detected — immediate
  attention recommended").
- **Cluster Health Score** — a 0–100% gauge chart derived from node
  readiness, component health, pod health, and warning-event counts.
- **Key Metrics** — KPI tiles for total Errors / Warnings / Info signals
  counted across all parsed sections.
- **Pod Status** — a Running vs. Not-Running pod donut chart (only shown
  when pod counts could be extracted from the log).
- **Top Risks** — the top 3 highest-severity metrics (errors/warnings)
  called out as a quick-glance risk list.
- **AI Executive Briefing** — an opt-in ("Get AI Executive Briefing"
  button) natural-language summary generated by the headless GitHub
  Copilot CLI from the parsed analysis. Not run automatically because it
  can take 1–2 minutes per request.

### 4. Detailed Analysis tabs (`#analysisTabs`)
A tab bar with four tabs, shared between the home page and the (currently
unlinked/legacy) Deep-Dive page:

#### a. Cluster Health Analysis
Only populated when the upload contains a `cop_sanity_logs*.log` file.
Shows every `STEP:` section from that log as an expandable/collapsible
card, colour-coded by severity (red = error, amber = warn, blue/grey =
info/neutral) based on keyword detection in each section's log lines.
Several section titles get specialized table rendering instead of raw
text:
- **`lspodnr` (pods that are NOT Running/Completed)** and **`lspod` (all
  pods, all namespaces)** — rendered as sortable tables with columns
  Namespace, Name, Ready, Status, Restarts, Age.
- **`noderesource` (node resource usage, excluding containerd rows)** —
  rendered as a per-node table with columns Node-FQDN, Uptime, Load
  Average, Memory, POD Count, and Disk Usage of `/dev/sda6`.
- **Per-node containerd image count** — rendered as a per-node table of
  containerd image counts.
- **Disk usage** sections — rendered as a per-node disk-usage table.
- Any other `STEP:` section falls back to a generic table (if the content
  looks tabular) or a plain colour-highlighted line list.

#### b. Logs Analysis
Only populated when the upload was a `.tar`/`.tar.gz`/`.zip` archive
(rather than a single `.log` file). Shows the extracted archive's
directory/file contents as tabs, with RCA (root-cause) pattern matches
highlighted and optionally cross-referenced against Jira/Confluence via
`POST /api/rca-lookup`.

#### c. IVT Report
Only populated when the upload contains file(s) with `ivt` in the file
name. Parses and displays Install Verification Test results for the
supported app types (e.g. `replace_node`, `add_node`, `ipsec`, `dns`,
`ntp`, `etcd`, `disk`, `pv`, `postgres`, etc.) with pass/fail status per
check.

#### d. Deep Search
Independent of the current upload's analysis — lets you search across the
raw/extracted content of **any** file uploaded in the last 30 minutes
(server-side retention window; see `deepSearch.js`). Supports plain
keyword search, regex, and simple `AND`/`OR` combinators (e.g.
`error AND timeout`, `CrashLoopBackOff OR OOMKilled`). Includes a
**Browse Files** sub-panel to pick a directory and file from a recent
upload and view its raw content directly, without running a search.

## Deep-Dive page (`deep-dive.html`)
A standalone, full-page version of the "Detailed Analysis" tabs (section
4 above), reading the most recently analyzed upload's data from
browser-local storage rather than a fresh upload. Not currently linked
from the home page's navigation; reachable only by direct URL.

---

## Backend modules (for reference)

| File | Purpose |
|---|---|
| `server.js` | Express app: routes for upload, Copilot narrative, RCA lookup, and all Deep Search endpoints. |
| `analyzer.js` | Parses a single `cop_sanity_logs*.log` file into sections, builds the summary/KPI/chart data. |
| `archiveExtractor.js` | Extracts `.tar`/`.tar.gz`/`.zip` uploads to a temp directory. |
| `archiveAnalyzer.js` | Walks an extracted archive, analyzing any `cop_sanity_logs*` and `*ivt*` files found inside. |
| `ivtAnalyzer.js` | Parses IVT (Install Verification Test) report files. |
| `copilotNarrator.js` | Calls the headless GitHub Copilot CLI to generate the AI Executive Briefing text. |
| `rcaLookup.js` | Cross-references detected issues against Jira/Confluence for related tickets/docs. |
| `deepSearch.js` | In-memory index + TTL eviction powering the Deep Search tab. |
